shader-garden

A small Three.js + GLSL playground that actually has good ergonomics. ~12 shaders, hot-reload that preserves uniform state, and a declarative uniform protocol.

Three.jsGLSLReactViteTypeScript
View on GitHub

The problem

Fragment shaders are addictive but the ergonomics around iterating on them are bad. Hot-reload usually breaks. GLSL error messages are cryptic. State management between uniforms and the host React component is a mess. You end up reloading the page every time you change a number.

I wanted a workflow that didn't fight me. Open a .frag file, change something, see the result instantly. If the shader has a syntax error, recover gracefully when I fix it. If I tweak a uniform live, preserve that value across hot reloads.

The approach

Three components, each doing one thing well:

  1. Vite + vite-plugin-glsl — gets us GLSL imports and HMR. Free.
  2. A React harness — a tiny app that scans src/shaders/ for .frag files, mounts a Three.js ShaderMaterial on a fullscreen quad, and provides controls.
  3. A uniform protocol — every shader auto-receives u_time, u_resolution, u_mouse. Custom uniforms are declared in a sidecar .json file, surfaced as sliders.

Hot-reload that actually works

The default Three.js HMR path tears down the whole material on shader change, which means uniform values reset to their defaults. Annoying when you've been dragging a slider for 20 minutes.

The fix is small: cache uniform values keyed by shader ID, and on rebuild, copy them onto the fresh uniforms object before reassigning to the material. src/harness/hot-reload.ts has the gory details.

hot-reload.ts
const uniformCache = new Map<string, Uniforms>();

export function getOrPreserveUniforms(shaderId: string, fresh: Uniforms): Uniforms {
  const cached = uniformCache.get(shaderId);
  if (!cached) {
    uniformCache.set(shaderId, fresh);
    return fresh;
  }
  for (const key of Object.keys(fresh)) {
    if (key in cached && cached[key].value !== undefined) {
      fresh[key].value = cached[key].value;
    }
  }
  uniformCache.set(shaderId, fresh);
  return fresh;
}

The uniform protocol

Most live-coding shader environments either give you no controls or give you a bunch of controls and let you wire them up imperatively. I wanted something in between: declarative, but no boilerplate.

Drop a 01-flow-field.frag, optionally drop a 01-flow-field.json next to it:

01-flow-field.json
{
  "u_speed": { "type": "float", "min": 0, "max": 2, "default": 1 },
  "u_color_a": { "type": "color", "default": "#1a232f" },
  "u_color_b": { "type": "color", "default": "#e87a3e" }
}

The harness reads it, builds a controls panel, surfaces the values to the shader. No code changes needed.

The repo currently has shaders for FBM-domain-warped flow fields, Truchet tile patterns, Mandelbulb SDF raymarching, and a few others. New ones go up roughly monthly when I have a free evening.

Lessons

Hot-reload that loses state is worse than no hot-reload. The first version of this had no uniform preservation; I'd reload the page out of frustration after a few edits. The cache trick takes 30 lines and changes the experience completely.

Don't fight the build tool. I considered writing a custom dev server. vite-plugin-glsl already exists and is good. Use it.

Declarative beats imperative for hobby projects. JSON sidecars feel slightly inelegant compared to "just write a hook in your shader file" — but they're trivially parseable, no parsing-out-comments-with-regex, and they survive shader rewrites.

What I'd do differently

Skip the React harness next time. It's overkill for what's essentially "render a fullscreen quad with the latest shader." A vanilla Three.js setup with a small controls library would be ~200 lines instead of ~600, and the harness's React state hasn't given me much in return.
