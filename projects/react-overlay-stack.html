react-overlay-stack

Headless modal/drawer/popover stack manager for React. Focus traps, ESC stack semantics, scroll lock, restore focus — done correctly. No styling opinions.

ReactTypeScriptAccessibilityHeadless UI
View on GitHub

The problem

Every project I've worked on has reinvented the same overlay logic: focus traps, ESC-to-close, scroll lock, z-index sanity. Often badly. Often differently in three places within the same app.

This isn't React's fault — it's a category of UI state that's surprisingly subtle:

  • Focus trap — Tab cycles within the topmost overlay; Shift+Tab does the right thing.
  • ESC handling — Only the topmost overlay closes. Nested overlays don't all collapse at once.
  • Body scroll lock — Lock when first overlay opens, unlock when last closes. Restore prior overflow style cleanly.
  • Restore focus — When an overlay closes, focus returns to the element that opened it.
  • Stack-aware z-index — Topmost overlay should always render on top of others, no matter the source order.

I wanted a headless library that handled all of this correctly, with no styling opinions, that I could drop into any React project.

The approach

Three layers, each isolated:

  1. OverlayProvider — context with a stack of {id, close} entries
  2. useOverlay() — hook that gives you {isOpen, open, close, dialogProps}
  3. scroll-lock + inert — body scroll lock and accessibility quarantine

The stack state machine

Stack push on open, pop on close. topmost() tells you which overlay should respond to ESC and which should hold the focus trap.

provider.tsx
type StackEntry = { id: string; close: () => void };

export const OverlayContext = createContext<{
  stack: StackEntry[];
  push: (entry: StackEntry) => void;
  pop: (id: string) => void;
  topmost: () => StackEntry | undefined;
}>(null!);

ESC that respects nesting

The original ESC implementation registered a global keydown listener at every overlay level. Result: pressing ESC closed every open overlay, all at once. Issue #1 from the wild.

The fix: a single global listener, with each overlay's hook checking ctx.topmost()?.id === id before reacting. Only the topmost overlay closes; any others stay open. e.stopPropagation() prevents bubbling further.

use-overlay.ts (excerpt)
useEffect(() => {
  if (!isOpen) return;
  const onKey = (e: KeyboardEvent) => {
    if (e.key === 'Escape' && ctx.topmost()?.id === id) {
      e.stopPropagation();
      close();
    }
  };
  document.addEventListener('keydown', onKey, true);
  return () => document.removeEventListener('keydown', onKey, true);
}, [isOpen, id]);

Scroll lock that doesn't break

The naïve "set body.overflow = 'hidden'" approach has two failure modes:

  1. If the user already had a custom overflow style, you clobber it.
  2. Scrollbar disappearing causes a layout shift.

Fix: ref-count the locks; first open captures original overflow + computes scrollbar width and applies padding-right; last close restores. Code is in scroll-lock.ts.

Inert for older browsers

Modern browsers support the inert attribute (Chrome 102+, Firefox 112+, Safari 15.5+). For older browsers, the polyfill walks all focusable descendants and saves their tabindex, then sets it to -1. Restores on close.

API in practice

SettingsModal.tsx
function SettingsButton() {
  const overlay = useOverlay({ id: 'settings-modal' });

  return (
    <>
      <button onClick={overlay.open}>Settings</button>

      {overlay.isOpen && (
        <div role="dialog" {...overlay.dialogProps}>
          <h2>Settings</h2>
          <button onClick={overlay.close}>Close</button>
        </div>
      )}
    </>
  );
}

That's it. No portals, no styles, no animations — bring your own. The library handles the state machine, focus, scroll lock, and accessibility plumbing. You handle pixels.

Lessons

Overlay logic is high-leverage. Every product has overlays. Every product gets them subtly wrong. A correct headless implementation pays for itself in audit findings avoided.

Headless = freedom. No styling = library users don't fight the design system. They get the hard parts (state, a11y, focus) and own the easy parts (pixels).

Test the keyboard flow, not just the click flow. The first version had RTL tests that opened/closed via fake clicks. None of them caught the ESC-bubbling bug. Adding a test that actually presses ESC found three more issues.
